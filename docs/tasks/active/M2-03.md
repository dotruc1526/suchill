### Consumer API handoff for the three P1 fixes

- VN: `progress.saveEpisodeCheckpoint({lessonId, blockId, storyVersionId, operationId, currentSceneId, visitedSceneIds})`; use `recordChoice({lessonId, blockId, storyVersionId, operationId, sceneId, choiceId})` for locked selections. `getEpisodeProgress(storyVersionId)` reads session-owned history.
- Video: `progress.saveVideoPosition({lessonId, blockId, operationId, positionSeconds, watchedRanges})`; `getVideoProgress(lessonId, blockId)` returns position/ranges without granting completion.
- Resume: `progress.getResumePoint(lessonId)` returns a discriminated `block` / `visual_novel` / `video` result. Without progress it uses the first block by authored order; VN includes pinned version/scene, video includes position.
- Quiz: render `questions[].options` in the returned order with stable IDs and Vietnamese labels. `explanation` is no longer sent before answering; successful scored receipts carry `feedback[].explanation`.
- Media: use `url`, `poster`, `captionTracks`, `transcript` and `fallback`. Consumers no longer resolve `storageRef`/caption/transcript refs themselves. Fixtures supply published `mediaResources` for the referenced caption/transcript records.
