## Hưng re-review remediation (round 3) + main integration — 2026-10-01

- Addressed Hưng's P1 at head `1c66037`: `update()` applied every settled action result without checking whether the story context or services had changed mid-flight. An action started on story A could resolve after the same instance loaded story B and overwrite B's UI with A's session (with later handlers mixing B's services/context and A's session).
- Added `VisualNovelActionGate` to `visualNovelModel.ts`, mirroring the accepted `QuizSubmissionGate` pattern: `activate(contextKey)` on render, `invalidate()` in the load effect (covers services swaps and retry reloads with an unchanged key), `begin()` per action, and `isCurrent(token)` before applying. `update()` now captures a token before `await` and returns early when stale, so `busy`/`setState` of the new story are never touched. Already-sent saves still complete server-side (idempotent); only their UI application is gated.
- Added behavioral regressions that execute the real race through real model functions with deferred mock saves and overlapping scene IDs: A pending → B ready → A resolves (success is discarded, UI stays B) and A pending → B ready → A fails offline (no stale error screen on B), plus same-context invalidate coverage and a current-action control. Component wiring (activate/invalidate/begin/isCurrent call sites in `update()`) is pinned by a source test.
- Test-harness note: the repo has no DOM renderer (deps are react/react-dom only; package.json/lockfile is an excluded hotspot for this task), so the A→B race is verified behaviorally at gate+model level rather than through React rendering. If Hưng requires DOM-level coverage, that needs a separate test-infra claim.
